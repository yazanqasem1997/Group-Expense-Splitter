Build a reusable keyword-based classification and icon system for both:

1. Expense records in the **Expenses tab**
2. Individual entries in the **Itemization section**

The system must return two separate values:

* `category`: the high-level expense category
* `iconKey`: the most relevant specific icon for the expense or item

For example:

* `Mineral water 500ml` → category: `Food & Beverages`, iconKey: `water`
* `Cappuccino` → category: `Food & Beverages`, iconKey: `coffee`
* `Uber trip` → category: `Transport`, iconKey: `taxi`
* `Emirates flight` → category: `Transport`, iconKey: `flight`
* `Hotel room` → category: `Accommodation`, iconKey: `hotel`

Use the high-level category for filters, totals, charts and reporting. Use the specific icon to make individual expenses and itemized entries easier to recognize.

## High-level categories

1. `Food & Beverages`

## Text normalization

Before attempting a match, normalize the expense or item text:

1. Convert it to lowercase.
2. Remove leading and trailing spaces.
3. Replace repeated spaces with a single space.
4. Remove punctuation that does not affect meaning.
5. Normalize accented characters where appropriate.
6. Keep both the original text and normalized text.
7. Remove quantity and packaging expressions from the matching copy:

   * `x2`
   * `2 x`
   * `500ml`
   * `1.5l`
   * `250g`
   * `2kg`
   * `pack`
   * `packet`
   * `bottle`
   * `pcs`
8. Do not remove words that indicate the item’s meaning.
9. Use whole-word or phrase matching to avoid false matches.
10. Support basic singular and plural matching.

Examples:

* `Mineral Water 500ML x2` → `mineral water`
* `UBER TRIP #9281` → `uber trip`
* `Hotel Room – 2 Nights` → `hotel room nights`

## Classification priority

Apply matching rules in this exact order:

1. User-created rules
2. High-priority contextual phrases
3. Exact normalized item or expense matches
4. Known merchant matches
5. Whole-phrase keyword matches
6. Whole-word keyword matches
7. Conservative fuzzy matching
8. Parent expense context for itemized entries
9. Existing manually selected category
10. `Other`

Do not allow a weak fuzzy match to override a strong exact or phrase match.

Return:

```ts
{
  category: "Food & Beverages",
  iconKey: "water",
  confidence: 0.98,
  matchedRule: "exact_alias:mineral water",
  source: "automatic"
}
```

## Context and conflict resolution

Create explicit priority rules for ambiguous words and phrases.

### Water

* `water`, `bottled water`, `mineral water` → Food & Beverages / water
* `water bill`, `water utility` → Bills & Utilities / water-utility

### Gas

* `petrol`, `diesel`, `gas station`, `vehicle fuel` → Transport / fuel
* `gas bill`, `natural gas utility` → Bills & Utilities / gas

### Ticket

* `flight ticket`, airline name or airport context → Transport / flight
* `train ticket`, railway context → Transport / train
* `bus ticket` → Transport / bus
* `museum ticket`, `cinema ticket`, `event ticket` → Activities & Entertainment / relevant activity icon
* A generic `ticket` with no transport context → Activities & Entertainment / ticket

### Uber

* `Uber`, `Uber trip`, `Uber ride` → Transport / taxi
* `Uber Eats` → Food & Beverages / food

### Delivery

* A complete food-delivery expense → Food & Beverages / food
* A separate `delivery fee` item → Fees & Taxes / delivery-fee
* A courier or parcel-delivery service → Fees & Taxes / delivery-fee

### Hotel

* `hotel room`, `hotel stay` → Accommodation / hotel
* `hotel restaurant`, `room-service meal`, `breakfast` → Food & Beverages / food
* `hotel city tax` → Fees & Taxes / tax

### Phone

* A purchased phone or phone accessory → Shopping / electronics
* Phone bill, data package or mobile plan → Bills & Utilities / phone

### Bar

* Drinks purchased at a bar → Food & Beverages / alcohol
* Club or event entry fee → Activities & Entertainment / nightlife

### Apple

* Apple Store, iPhone, MacBook or electronics context → Shopping / electronics
* Apple fruit or grocery context → Food & Beverages / groceries

Use the most specific meaningful phrase before matching a generic individual word.

## Expense-level classification

For a normal expense record, classify using:

1. Expense title
2. Merchant
3. Description
4. Existing notes
5. Existing category
6. Itemized lines, if available

If the expense contains itemized lines from multiple categories:

* Keep every item’s own category and icon.
* Determine the parent expense category using the category with the highest combined itemized value.
* If no category clearly dominates, preserve the user-selected parent category.
* Do not change split amounts or totals.

Example:

```text
Parent expense: Carrefour — AED 320

Water — AED 8
Food & Beverages / water

Groceries — AED 210
Food & Beverages / groceries

Shampoo — AED 42
Health & Personal Care / personal-care

Phone charger — AED 60
Shopping / electronics
```

The parent expense can be Food & Beverages because that category has the highest combined value, while each item keeps its own specific classification.

## Itemization behaviour

Apply the same classification engine to every individual itemized entry, regardless of how the item was created.

Each itemized record should support:

```ts
{
  id: string;
  originalName: string;
  normalizedName: string;
  quantity?: number;
  unitPrice?: number;
  total: number;
  category: ExpenseCategory;
  iconKey: ExpenseIconKey;
  confidence: number;
  matchedRule?: string;
  classificationSource: "automatic" | "user";
}
```

Display the specific item icon next to the item name.

Examples:

* Water → water icon
* Cappuccino → coffee icon
* Burger → food icon
* Petrol → fuel icon
* Parking → parking icon
* Museum ticket → museum icon
* Shampoo → personal-care icon
* VAT → tax icon

The item icon must not change the mathematical treatment of the item.

## User corrections and custom rules

Allow the user to manually change:

* Category
* Icon

When the user changes a category or icon, ask whether the choice should apply:

* Only to this expense or item
* To future matches with the same normalized name

Store reusable user rules separately from the default rules.

Example:

```ts
{
  normalizedTerm: "my special shop",
  category: "Shopping",
  iconKey: "gift",
  matchType: "exact",
  createdByUser: true
}
```

User-created rules must take priority over automatic rules.

Never overwrite a manual selection during later automatic reclassification unless the user explicitly requests it.

## Search integration

Use the same normalized item text for the Itemization search.

If the user searches for `water`:

* Match water, mineral water, bottled water and relevant aliases.
* Display every matching itemized entry.
* Show the combined total of matching item values.
* Do not add the full value of each parent expense.
* Count each matching item exactly once.
* Display the water icon beside applicable results.

The search should also match:

* Specific item names
* Merchant names
* Category names
* Icon keywords
* Known aliases
* User-created classification terms

Examples:

* Searching `coffee` finds cappuccino, latte and espresso.
* Searching `taxi` finds Uber, Careem and cab expenses.
* Searching `flight` finds airline and airfare expenses.
* Searching `Food & Beverages` finds all items assigned to that category.

Search matching must not change the stored category or icon.

## Performance and maintainability

* Keep the keyword maps in a separate configuration module.
* Keep the classification logic in a reusable service or utility.
* Do not duplicate keyword lists between Expenses and Itemization.
